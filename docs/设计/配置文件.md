# 配置文件

Cup的配置文件是在项目根目录下的Cup.toml文件，它包含了项目的所有信息

## `[package]`表
这个表包含了包的基本信息：
```toml
[package]
# 必须包含的字段
name = "<NAME>" # 包名
version = "0.1.0" # 语义化版本号
type = "executable" # 包类型，可选值：executable, static, shared, module, header-only
```

## `[build]`表
此表包含基本的构建过程配置信息
```toml
[build]
jobs = 4 # 构建时的并行任务数，如果为0则自动检索CPU核心数

[build.languages] # 这个子表用于指定项目启用的语言支持与语言的版本
C = "17"
```

## `[dependencies]`表
此表包含了项目依赖的其他包，Cup会自动下载并安装这些依赖:
```toml
[dependencies]
local = { path = "../package" } # 指示为本地依赖项
remote = { git = "owner/repo/v1.2.3" } # 指示为Git远程依赖项

[dependencies.dep]
path = "..." # 本地依赖项

# git 字段是包唯一限定名，它的格式为 `<owner>/<repo>/<tag>`
git = "..." # Git远程依赖项

features = ["feature1", "feature2"] # 指定传递给依赖项的功能表
default-features = false # 禁用默认功能，默认情况下它为 true
optional = true # 指示此依赖项为可选，可以在 [features] 表中通过特性启用，默认值为 false
```

此表左侧的键名决定了在代码中如何访问它们的[伪命名空间(参见关于符号冲突问题的解决方案)](符号冲突.md)：
```cpp
$local::function();
$remote::Class::method();
```

与它效果类似的还有一个`[dev-dependencies]`表，但该表指示的依赖项只会在库未被作为依赖项时启用（仅开发时）

## `[features]`表
此表包含了可选的功能，可以使包使用者根据需要启用或禁用：
```toml
[features]
default = ["feature2"] # 默认启用的功能，包使用者可以通过 default-features 选项禁用默认功能
# 定义功能
feature1 = [] # 功能1
feature2 = [] # 功能2

# 指定功能间的启用传递关系
feature3 = ['feature1'] # 当 feature3 被启用时，feature1 也会被自动启用
feature4 = ['dep'] # 当 feature4 被启用时，dep 依赖也会被引入
```

## `[[executable]]` 表数组

这个表数组用于指定可执行文件的名称与main函数所在文件的路径，例如：
```toml
[[executable]]
name = "my-program"
src = "src/main.cpp"

# 可选参数
default-features = false # 禁用默认功能
features = ["feature1"] # 此可执行文件需要的功能
```
如果未带任何参数运行 cup run，则 cup 会自动选择第一个表对应的可执行文件作为运行目标

## Config 表

所有拥有以下字段的表都是 Config 表：
```toml
defines = ["MY_DEFINE"] # 预定义的宏
includes = ["include"] # 头文件搜索路径
link-paths = ["path/to/libs"] # 链接库搜索路径
link-libraries = ["lib1", "lib2"] # 链接库
compile-options = ["-Wall", "-Wextra"] # 编译选项
compile-features = ["cxx_std_17"] # 编译特性
link-options = ["-Wl,-rpath,path/to/libs"] # 链接选项
```

以下的表都是 Config 表：
```toml
[build.debug]
[build.release]

# 以下引号中的键可以是正则表达式
# 只有对应的 feature 处于启用状态时才引入
[feature."FEATURE".debug]
[feature."FEATURE".release]
# 只有目标为 TARGET 时才引入
[target."TARGET".debug]
[target."TARGET".release]
# 只当构建系统采用指定的生成器才引入
[generator."GENERATOR".debug]
[generator."GENERATOR".release]
```
